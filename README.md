# Crypto Signal Bot — сканер рівнів на Coinbase (v2)

Бот сканує топ-20 пар з Coinbase (за обсягом торгів, котирування в USDC), шукає
цінові рівні за методологією з книги (Герчик, "Курс активного трейдера") і шле два
типи сповіщень у Telegram:

- 🔎 **Радар** — ціна наближається до сильного рівня (завчасне попередження)
- ✅ **Сигнал** — підтвердився один із 3 патернів (пробій / відбій / хибний пробій)

⚠️ **Бот нічого не торгує сам.** Тільки сповіщення. Рішення про вхід — завжди твоє,
після власного аналізу графіка.

---

## Крок 1. Створи Telegram-бота

1. Відкрий Telegram, знайди **@BotFather**.
2. Напиши `/newbot`, дай боту назву — отримаєш **TELEGRAM_BOT_TOKEN** (виглядає як
   `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`).
3. Напиши своєму новому боту будь-яке повідомлення (щоб він тебе "побачив").
4. Знайди **@userinfobot**, напиши йому — він покаже твій **chat_id** (число).

## Крок 2. Заведи GitHub-акаунт і репозиторій (якщо ще немає)

1. Зареєструйся на https://github.com (безкоштовно).
2. Створи новий **приватний** репозиторій, наприклад `crypto-signal-bot`.
3. Завантаж туди всі файли з цього проекту (через веб-інтерфейс "Add file → Upload
   files", або через git, якщо знайомий).

## Крок 3. Додай секрети в GitHub (щоб не світити токен у коді)

1. У репозиторії відкрий **Settings → Secrets and variables → Actions**.
2. Додай два секрети:
   - `TELEGRAM_BOT_TOKEN` — токен з кроку 1
   - `TELEGRAM_CHAT_ID` — твій chat_id з кроку 1

## Крок 4. Перевір список пар

Відкрий `pairs.json` — там уже є стартовий список 20 пар (USDC). Це орієнтовний
список, не гарантовано актуальний топ-20 за обсягом на цю секунду. Щоб отримати
точний актуальний топ-20, встанови залежності локально й запусти:

```bash
pip install -r requirements.txt
python update_pairs.py
```

Це перезапише `pairs.json` реальними топ-20 парами з Coinbase. Далі можеш вручну
редагувати файл — додавати чи прибирати будь-які пари.

## Крок 5. Увімкни GitHub Actions

1. У репозиторії відкрий вкладку **Actions**.
2. Якщо GitHub запитає — підтверди увімкнення Actions для репозиторію.
3. Знайди workflow **"Crypto Signal Scan"** — він вже налаштований на запуск кожні
   15 хвилин автоматично (`.github/workflows/scan.yml`).
4. Щоб перевірити одразу, не чекаючи розкладу: відкрий workflow → **Run workflow**
   (кнопка справа) → запусти вручну.

## Крок 6. Перевір результат

Через кілька хвилин після запуску глянь у Telegram — якщо є сетапи, прийдуть
повідомлення. Якщо сетапів немає (нормально, це не щохвилини) — перевір вкладку
**Actions** у GitHub, що workflow відпрацював без помилок (зелена галочка).

## Структура проекту

```
crypto-signal-bot-v2/
├── main.py                    # головний скрипт — точка входу
├── config.py                  # усі налаштування (таймфрейми, пороги, ризик)
├── pairs.json                 # список пар для сканування — редагуй вручну
├── update_pairs.py            # разово перегенерувати pairs.json топ-20 за обсягом
├── data_fetcher.py            # отримання свічок з Coinbase (ccxt)
├── levels.py                  # пошук і оцінка сили цінових рівнів (методологія з книги)
├── strategy.py                # 3 патерни: пробій / відбій / хибний пробій
├── state.py                   # пам'ять бота (state.json) для логіки ретестів радару
├── indicators.py               # RSI, обсяг — додатковий контекст у повідомленнях
├── telegram_notifier.py       # формат повідомлень + надсилання
├── .github/workflows/scan.yml # розклад автозапуску (GitHub Actions)
└── requirements.txt
```

## Що можна налаштувати в `config.py`

- `RADAR_DISTANCE_PCT` — на якій відстані від рівня слати радар (зараз 1.5%)
- `RETEST_MOVE_AWAY_PCT` — на скільки % ціна має відійти, щоб наступне наближення
  рахувалось як ретест (зараз 2%)
- `MIN_RISK_REWARD_RATIO` — мінімальне співвідношення прибуток:ризик (за книгою — 3:1)
- `LEVEL_TIMEFRAME` / `SIGNAL_TIMEFRAME` — таймфрейми для пошуку рівнів і підтвердження
- `MIN_TOUCHES_FOR_LEVEL`, `RADAR_MIN_LEVEL_STRENGTH` — пороги чутливості

Постав з обережністю, поспостерігай на реальних даних кілька днів і адаптуй — сам
запропонував такий підхід, і це правильно: параметри книги — гарна відправна точка,
а не догма.

## Відомі обмеження цієї версії (MVP)

- Рівні перераховуються з нуля щоразу — ідентифікація одного й того ж рівня між
  запусками робиться за округленою ціною (може іноді "губити" рівень при дрібних
  розбіжностях розрахунку).
- Типи рівнів з книги (історичний / дзеркальний / лімітний / паранормальна свічка
  і т.д.) поки об'єднані в загальну формулу сили, а не розрізняються явно.
- Немає бек-тестингу — поки що це "сирий" сканер, точність стратегій ще не
  перевірена на історії.

Ці пункти — природні наступні кроки, коли назбирається практика використання.
