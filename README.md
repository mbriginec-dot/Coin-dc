# Торговий сигнальний бот — рівнева торгівля (акції, ф'ючерси, крипто, форекс)

Бот, побудований на основі вашої власної методології рівневої торгівлі:
"Торговий алгоритм трейдера" + 7 стратегій (Відбій, Пробій, Хибний пробій,
Різкий імпульс, Торгівля в каналі, Сходинки, Поглинання) + авторська стратегія
"Ключові рівні дня" + адаптації під крипту та форекс.

Кожні 5 хвилин (налаштовується) бот:
1. Тягне ринкові дані для всього вашого watchlist (акції, ф'ючерси, крипто, форекс).
2. Будує рівні, рахує ATR, шукає формації всіх 8 стратегій.
3. Якщо формація ПОЧАЛА складатись (наприклад, БСУ+БПУ1, акумуляція, пробитий
   рівень в очікуванні розвороту) — надсилає РАННЄ попередження в Telegram.
4. Якщо формація ПІДТВЕРДИЛАСЬ — надсилає повний сигнал: точка входу, стоп,
   три тейк-профіти, обсяг позиції, ATR, % пройденого ATR сьогодні, комісія.

### 1. Джерела даних — не всі "справжній реальний час"

| Клас активу | Провайдер зараз | Що це означає |
|---|---|---|
| Крипто | **Coinbase Exchange** (публічний API, без ключа) | Справжній реальний час, безкоштовно |
| Акції | **yfinance** (Yahoo Finance, без ключа) | Неофіційна бібліотека, можлива затримка в секунди-хвилини, іноді нестабільна |
| Ф'ючерси | **yfinance** (безперервні контракти `ES=F`, `NQ=F` тощо) | Те саме застереження |
| Форекс | **yfinance** (`EURUSD=X` тощо) | Те саме застереження |

Для реальної торгівлі грошима на акціях/ф'ючерсах/форекс розгляньте платний
апгрейд: **Alpaca** (акції, безкоштовний рівень з реальним часом IEX),
**Polygon.io** чи **Interactive Brokers TWS API** (акції/ф'ючерси), **OANDA**
чи **Twelve Data** (форекс). Архітектура розв'язана саме для цього: досить
реалізувати новий клас `DataProvider` (див. `bot/data/base.py`, за зразком
`bot/data/coinbase_provider.py`) і вказати його як `provider:` у
`config/watchlist.yaml` — решта бота (стратегії, калькулятор, Telegram) не
зміниться.

### 2. Крипто-біржа: зараз Coinbase, заплановано Binance/Bybit

За вашим проханням крипто-провайдер — **Coinbase Exchange** (`bot/data/coinbase_provider.py`),
публічний REST API, тикери у форматі `BTC-USD`. Коли будете готові повернутись
на Binance чи Bybit — потрібно буде:
1. Створити `bot/data/binance_provider.py` (або `bybit_provider.py`) за зразком
   `coinbase_provider.py` — інтерфейс `DataProvider` однаковий.
2. Зареєструвати новий провайдер у `bot/data/aggregator.py` (`_build_provider`)
   — там уже є заглушки-нагадування з `NotImplementedError` саме на цей випадок.
3. Змінити `provider: coinbase` на `provider: binance` і тикери (`BTCUSDT`
   замість `BTC-USD`) у `config/watchlist.yaml`.

### 3. Комісії — заглушки, НЕ реальні тарифи

Жоден з ваших вихідних документів (Стратегія_1..7, калькулятори .xlsx) не
містить реальних тарифів брокера — лише порожнє поле для ручного вводу
("Комісія + прослизання, $"). `config/commissions.yaml` — **шаблон, який
потрібно заповнити вашими реальними цифрами** (тариф вашого брокера/біржі).
Бот жодним чином не вигадує ці цифри сам.

### 4. Що автоматизовано повністю, а що — наближено

| Компонент | Стан |
|---|---|
| Формули входу/стопу/тейку/обсягу (усі 8 стратегій) | **Точно** відтворені з ваших Excel-калькуляторів, перевірено юніт-тестами проти прикладів з ваших .docx (`tests/test_risk_calculator.py`) |
| ATR, % пройденого ATR | Точно за методикою калькуляторів |
| PDH / PDL / POC / 1H-High / 1H-Low (Ключові рівні дня) | Повністю автоматично — ця стратегія і в оригіналі побудована як об'єктивна |
| Рівні для Стратегій 1-7 (звичайні support/resistance) | **Наближено**: автоматичний фрактальний детектор екстремумів на денному графіку замість ручного проведення трейдером; **сила рівня рахується реально** (тижневий збіг, екстремум, дзеркальність, історія хибних пробоїв, межа каналу — усі 5 факторів). Можна доповнити вручну через `config/levels_override.yaml` |
| БСУ→БПУ1→БПУ2, акумуляція, поджаття, поглинання, сходинки | Автоматизовано на основі формальних правил з документів — але це завжди спрощення живого читання графіка людиною |
| Домашнє завдання (макроогляд, скринінг Finviz, вибір 3-5 найкращих сетапів) | **НЕ автоматизовано** — це свідомий вибір: методологія прямо каже, що це ручний, дискреційний етап |
| Ризик-ліміти на день/тиждень/серію збитків, психологічний чек-лист | **НЕ автоматизовано** — це про вашу дисципліну, бот лише рахує цифри для конкретного сетапу |

### 5. Відома розбіжність між вашими документами

У Стратегії 3 (Хибний пробій) числовий приклад у розділі 7.3 Word-документа
(ΔStop=0.47, 106 акцій) **не узгоджується** з формулою у самому Excel-файлі
(яка бере `MIN()` серед хвіст+буфер і двох резервних методів — і в цьому
прикладі обрала б значення 0.10, а не 0.47). Бот реалізує САМЕ формулу з
Excel (`bot/risk/calculator.py::false_breakout_stop`), оскільки вона
джерело істини ("усі формули документа відповідають формулам у таблиці").
Перевірте `tests/test_risk_calculator.py::test_false_breakout_strategy3_matches_excel_min_formula`
і вирішіть, чи саме така поведінка резервних методів вам потрібна.

```bash

cd trading-signal-bot
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
```

### Налаштування Telegram

1. Напишіть [@BotFather](https://t.me/BotFather) в Telegram → `/newbot` →
   отримаєте токен виду `123456:ABC-DEF...`.
2. Дізнайтесь свій `chat_id`: напишіть щось своєму боту, потім відкрийте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` і знайдіть `"chat":{"id": ...}`.
   Або скористайтесь ботом [@userinfobot](https://t.me/userinfobot).
3. Впишіть обидва значення в `.env`:
   ```
   TELEGRAM_BOT_TOKEN=123456:ABC-DEF...
   TELEGRAM_CHAT_ID=123456789
   ```
4. Перевірте: `python main.py --test-telegram`

### Налаштування watchlist і ризику

- `config/watchlist.yaml` — список інструментів (акції/ф'ючерси/крипто/форекс).
- `config/settings.yaml` — депозит, % ризику на угоду, R:R, пороги ATR тощо
  (за замовчуванням — точні значення з ваших калькуляторів).
- `config/commissions.yaml` — **обов'язково заповніть реальними тарифами**
  вашого брокера/біржі перед реальним використанням.
- `config/levels_override.yaml` — опційно: власноруч побудовані рівні, яким
  ви довіряєте більше за автодетектор.

## Запуск через GitHub Actions (бот працює на GitHub, без вашого комп'ютера)

У репозиторії вже є два готові файли: `.github/workflows/scan.yml` (сам бот,
за розкладом) і `.github/workflows/tests.yml` (CI — прогін тестів при кожному
push/PR). Після `git push` вони автоматично з'являються у вкладці **Actions**
вашого репозиторію.

### Налаштування (обов'язково перед першим запуском)

1. Відкрийте репозиторій на GitHub → **Settings → Secrets and variables →
   Actions → New repository secret**.
2. Додайте два секрети:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
3. Перейдіть у вкладку **Actions** → якщо GitHub попросить підтвердити
   workflow — натисніть **"I understand my workflows, go ahead and enable
   them"**.
4. Перевірте вручну: Actions → **"Сканування сигналів (кожні 5 хв)"** →
   **Run workflow** → зачекайте ~30-60 сек → перевірте, чи прийшло тестове
   повідомлення (або запис у логах кроку "Один прохід сканування").

Далі workflow запускатиметься сам за розкладом `*/5 * * * *` — нічого
додатково натискати не потрібно.

### Як зберігається стан між запусками

Кожен запуск GitHub Actions — це чистий одноразовий контейнер: без
`actions/cache` файл `data/state.json` (він захищає від повторного
надсилання того самого сигналу щоцикл) губився б щоразу. Workflow `scan.yml`
відновлює його на початку (`cache/restore`) і зберігає в кінці
(`cache/save`) — це стандартний обхідний шлях GitHub для "змінюваного" кешу
(ключ кешу включає `github.run_id`, а `restore-keys` підхоплює останній
збережений стан).

### ⚠️ Важливі обмеження — прочитайте перед тим, як покладатись на це як на єдиний запуск

- **Точність розкладу не гарантована.** GitHub офіційно попереджає, що
  `schedule`-тригери можуть запускатися із затримкою під час високого
  навантаження на сервіс — це може бути не точно "кожні 5 хвилин", а
  "приблизно кожні 5-15 хвилин" у гірших випадках. Для стратегій, де важлива
  секундна точність (напр. Різкий імпульс на відкритті сесії), краще
  дублювати запуск на власному комп'ютері чи VPS через вбудований планувальник
  (`python main.py`, розділ "Запуск" вище).
- **Ліміт хвилин Actions.** Для **публічних** репозиторіїв GitHub Actions
  безкоштовний без обмежень. Для **приватних** — безкоштовний ліміт (наразі
  2000 хв/міс на плані Free) буде вичерпано за кілька днів при запуску
  кожні 5 хв (288 запусків/добу). Якщо ваш репозиторій приватний і ви не
  плануєте платити за додаткові хвилини Actions — тримайте репозиторій
  публічним (без реальних токенів у коді — вони в Secrets) або запускайте
  бота локально/на VPS замість GitHub Actions.
- **Автовимкнення при неактивності.** GitHub автоматично вимикає заплановані
  workflow, якщо в репозиторії 60+ днів не було жодного коміту. Якщо бот
  "раптом перестав присилати сигнали" — перше, що варто перевірити.
- **Немає гарантії, що попередній прохід уже завершився** до наступного
  тригера (`concurrency: cancel-in-progress: true` вирішує це, скасовуючи
  застарілий прохід — але вкрай рідко це може означати, що якийсь один цикл
  сканування "пропущено").

## Структура проєкту

```
.github/workflows/scan.yml               — сканування за розкладом (кожні 5 хв) через GitHub Actions
.github/workflows/tests.yml              — CI: тести при кожному push/PR
bot/
  models.py              — типи даних (Bar, Level, FormationAlert, TradeSignal, ...)
  config.py               — завантаження .env + config/*.yaml
  session.py               — торгові сесії (NYSE, форекс, крипто 24/7)
  engine.py                 — оркестрація: дані -> стратегії -> дедуплікація -> Telegram
  scheduler.py                — цикл "кожні N хвилин" без зайвих залежностей
  indicators/atr.py             — ATR точно за методикою калькуляторів
  risk/calculator.py             — формули входу/стопу/тейку/обсягу (усі 8 стратегій)
  risk/commissions.py             — оцінка комісії з config/commissions.yaml
  strategies/levels.py             — рівні, сила рівня, БСУ/БПУ1/БПУ2, поджаття, акумуляція
  strategies/patterns.py            — поглинання, сценарії хибного пробою, сходинки
  strategies/s1_bounce.py ... s8_key_levels.py — 8 стратегій
  data/base.py, coinbase_provider.py, yfinance_provider.py, aggregator.py
  notify/telegram.py                 — форматування й надсилання повідомлень
  state/store.py                      — дедуплікація повідомлень (JSON-файл)
config/                                — settings.yaml, watchlist.yaml, commissions.yaml, levels_override.yaml
docs/STRATEGY_REFERENCE.md               — конспект усіх формул/правил стратегій
tests/                                    — юніт- та інтеграційні тести
main.py                                    — точка входу
```
